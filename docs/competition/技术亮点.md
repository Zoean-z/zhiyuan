## 一、推荐引擎质量

### 1.1 位次一票否决

**问题**：位次差距超出模型区间（rankGap < -3000，即院校最低位次比考生高 3000 名以上）的学校，因某一年分数线碰巧偏低被分数口径救回推荐——消融实验前此类"位次不可能"条目达 264 条。

**方案**：位次数据齐全且差距超出区间时，位次判定拥有否决权，概率强制 0、策略置空、不予推荐；仅位次数据缺失时才回退单分数口径。

**验证**：消融实验（A0→A1）对四组考生档案（湖南物理 588/560/620、广东物理 580）全量对比：

| 档案 | A0 不可能条目 | A1 不可能条目 | A0 RUSH 纯度 | A1 RUSH 纯度 |
|------|------|------|------|------|
| 湖南物理 588 | 82 | **0** | 31% | **100%** |
| 湖南物理 560 | 132 | **0** | 23.8% | **100%** |
| 湖南物理 620 | 23 | **0** | 85.2% | **95.8%** |
| 广东物理 580 | 27 | **0** | 18.8% | **100%** |

- 实现：`RecommendationPolicyService.explain()` rankVeto 分支
- 测试：`RecommendationPolicyServiceTest` 3 个否决用例

### 1.2 逐校年份窗口

**问题**：候选集按全省 `MAX(admission_year)` 过滤，零星补入新年份演示数据即导致全局年份窗口被"顶高"，真实 2024/2025 数据整体落空（推荐池从 38 所仅剩演示校）。

**方案**：`AdmissionCutoffMapper.findLatestByProvinceAndSubject` 改为逐校相关子查询：

```sql
AND c.admission_year = (
  SELECT MAX(c2.admission_year) FROM admission_cutoff c2
  WHERE c2.province = c.province
    AND c2.subject_type = c.subject_type
    AND c2.university_id = c.university_id
)
```

**效果**：推荐候选池从 38 所（仅演示校）恢复至 1,555 所真实院校，位次从千篇一律 25204 变为各校真实值。

- 实现：`AdmissionCutoffMapper.java:155-161`

---

### 1.3 全量梯度返回

**变更**：每梯度不再截取 Top5，按概率降序返回全部达标候选（实测冲 27/稳 39/保 692）。

四级比较器排序：概率降序 → 位次差降序 → 分数差降序 → 院校名。

- 实现：`RecommendationService.java:90-155`；`RecommendationPolicyService.recommendationComparator():92-98`

---

### 1.4 专业筛选 fail-closed

**问题**：专业筛选解析为空时静默退化为"不过滤"（L-08 同族），用户选了专业却看到全部学校。

**方案**：`majorId != null` 时无条件初始化为空集合（fail-closed），禁止 null 静默退化为"不过滤"。

- 实现：`UniversityQueryService.java:215-228`

## 二、AI 对话 Agent

### 2.1 四层决策链路

Agent 决策不再是简单的"AI 优先、规则兜底"双层，而是四层逐步精化、逐层降级的链路：

| 层 | 机制 | 开销 | 适用场景 |
|---|------|------|---------|
| ① 词典规则 | 意图词表外置 JSON（29 组），布尔组合匹配 | 零（无 LLM） | 强意图直接短路（推荐/画像/方案/删除/保存/详情） |
| ② 校准语义路由 | 类型化 Choice/Noul + 校准置信度门控 | LLM 一次调用 | 高置信（≥阈值）短路；默认关，shadow 可旁路对账 |
| ③ LLM 原生函数调用 | OpenAI tools/tool_choice=auto，工具 Schema 自动派生 | LLM 一次调用 | 模糊语义兜底 |
| ④ JSON 约束降级 | 提示词约束输出 JSON | LLM 一次调用 | 函数调用通道异常时降级 |

**关键设计**：
- 词典层对强意图直接短路，零 LLM 开销
- 校准路由层默认关，shadow 模式旁路对比，active 模式高置信短路且仅限白名单业务工具
- reply 合成工具：LLM 认为无需业务工具时选择 reply 直接回复
- 工具硬失败由失败改写层处理（见 2.2）

- 实现：`AgentDecisionService.java:88-138`

---

### 2.1b 意图词表外置 + DialogState 单次遍历

- **词表外置**：意图同义词全部外置 `agent/intent-keywords.json`（fail-fast 加载，顺序敏感清洗链），代码只保留组合/排除布尔结构；契约测试钉住每个组名与最小规模，词表损坏启动即报。
- **DialogState**：recentMessages 原 5 处反向扫描（学校续指/删除确认/方向填槽/推荐快照/志愿单快照）合并为单次遍历，各扫描的信任边界与"首中即停"规则逐条保留（专项等价测试 15 例）；本地路由、删除闸门、LLM 提示词三处消费同一份派生事实。
- **专业目录兜底**：`AgentMajorCatalogService` 内存缓存目录（5min TTL），关键词提取失败时按"唯一最长命中"兜底，归一化绝不硬拒绝（保住推荐引擎优雅降级）；落点在汇合层（Facade），同时覆盖本地提取与 LLM 参数两条路径。

---

### 2.2 失败改写层

**问题**：Agent 调用内部工具时，如果数据未覆盖（如查"哈佛大学"），旧版直接显示红色报错"当前数据集暂未收录该校"，用户不知道下一步怎么办。

**方案**：只读工具硬失败时，将用户原话 + 失败工具名与原因交给 LLM，由它用通用知识给出有帮助的回复。安全约束：

- 强制标注"（以下为通用信息，非本系统数据）"
- 禁止编造分数、位次、概率
- 志愿单写操作不送 LLM 改写（保持确定性引导）
- fail-open：LLM 异常时回退旧话术
- 开关 `ai.agent.failure-rewrite.enabled`（默认开）

**实测**：查"哈佛大学" → 中性灰条"系统数据未命中，已由 AI 结合通用知识补充解答" + LLM 回复"哈佛暂未收录…（以下为通用信息，非本系统数据）哈佛是美国私立研究型大学…"

- 实现：`AgentFailureRewriteService.java`；`AgentChatService.java:265-266`
- 前端：`AgentWorkspace.vue` 中性提示 `gk-tool-miss`

---

### 2.3 删除确认安全升级

**问题链**：
1. LLM 兜底生成的确认话术带空格（"确认删除第 **1** 个"），本地检测按无空格匹配失败 → 确认链路断裂
2. 用户删除请求不含"志愿/方案"名词（"删除第1个"），planNouns 前置条件过严 → 误判为无待确认

**方案**：
- 匹配前空白归一化（`replaceAll("\\s+","")`）
- 前置条件放宽为删除动词即可（助手确认提示本身已是凭证）
- 否定守卫（先不/不用/不确认/暂不/取消删除）阻止误确认
- 语义确认独立开关（Noul ≥ 0.9 才放行，fail-closed）

- 实现：`AgentDialogState.hasPendingDeleteConfirmation()`；`AgentDecisionService.java:446-449`
- 测试：`AgentDecisionServiceTest.llmGeneratedConfirmation_withSpaces_stillExecutes`

---

### 2.4 addPlanItem 按名校验

**问题**：用户说"把中南大学加入志愿单"，系统默认加推荐第 1 项（可能是其他学校）。

**方案**：决策层传递 `schoolName` 参数；执行层在最近推荐载荷中按校名匹配——命中则加入对应项，未命中则明确告知"最近一轮推荐中没有「X」"。

- 实现：`AgentDecisionService.java`（addPlanItem 分支传参）；`AgentToolFacade.resolveSelectedRecommendationItem()`

### 3.2 数据分级

每条专业录取线标注三级血缘字段：

| 字段 | 说明 |
|------|------|
| data_kind | REAL（真实）/ SIMULATED（演示） |
| calibration_source | 校准来源（如 Gaokao-Compass-11M） |
| simulation_rule | 演示行生成规则（如 HN-DEMO-V1） |

前端卡片展示"比赛验证数据"标注，让用户明确知道数据性质。

### 3.3 逐校年份窗口

专业录取线查询按 (university, province, subject_type) 相关子查询取每校各自最新年份，消除全局 MAX(year) 被零星演示数据毒化的风险（L-06 根修）。计划数/专业数聚合（aggregatePlanByUniversity）同样改为逐校窗口。

### 3.4 真实数据三源合流（16.6 万行全 REAL）

| 源 | 许可/方式 | 供给 |
|---|---|---|
| Gaokao-Compass-11M（HuggingFace） | MIT | 7 省院校线/专业线/一分一段/招生计划（163,928 行 REAL 专业线） |
| 软科公开 API（bcur_type=10 总榜 812 所） | 官方公开榜单 | soft_ranking 590 所 + 院校类型 12 类 |
| 掌上高考学校列表 API | 公开接口分页 2,991 所 | 类型/办学性质/985/211/双一流全量标准化 |
| 教育部《本科专业目录 2024》官方 PDF | 官方文件 pypdf 结构化解析 | 专业目录扩至 657（13 门类） |

导入管线四件套模板化（esc/num/norm/read_rows），stdout SQL + 幂等写（NOT EXISTS / ON DUPLICATE KEY UPDATE）；每轮导入后由独立审查智能体只读复核（基线完整性/数据质量/应用效果三段清单），共 5 轮闭环，抓出并修复孤儿专业表、年份窗口毒化、标签序列化缺陷三类问题。

### 3.5 排行榜真实化

`/api/universities/ranking`（逐校 soft_ranking 升序 + 类型过滤）驱动院校排行页真实榜单：来源标注"软科中国大学排名 2025，官网公开榜单入库"，590 所可分页浏览，行内直达院校详情——替换旧设计"不展示本地生成榜单"的空态页。

## 六、安全可靠性

### 6.1 删除操作多重防护

| 层 | 机制 |
|---|------|
| 决策层 | 否定守卫（先不/不用/不确认/暂不） |
| 确认层 | 空白归一化匹配 + 语义确认（≥0.9 fail-closed，默认关） |
| 执行层 | removePlanItem 缺参/不可解析 → 请用户指明 |

### 6.2 加入选校验

addPlanItem 传递 schoolName 参数，在最近推荐载荷中按名匹配——未命中则显式拒答。

### 6.3 DB_SCHEMA_INIT_MODE 安全默认

默认 `never`（生产 java -jar 不再 DROP 全表）；全新空库由 initdb 或手动 `always` 首次执行。

## 1. 设计目标

用三点描述：降低志愿决策信息负担；把规则与证据说清；让关键写操作可确认、可撤回/可追踪。

## 2. 设计原则

- 决策优先：突出条件、结果差异和下一步，不用装饰抢占信息层级；
- 风险可见：冲/稳/保同时使用文字、颜色和解释，不只靠颜色；
- 状态完整：加载、空数据、错误、离线、降级、无权限都有界面；
- 操作安全：保存/删除/角色调整明确对象、影响和确认；
- 真实截图：统一来自同一提交版本与固定演示数据。

## 3. 信息架构

```text
未登录：登录/注册 → 完善报考资料
普通用户：推荐查询 / AI 对话 / 历史记录 / 志愿方案
管理员：用户管理 / 院校 / 专业 / 院校录取线 / 专业录取线
```

说明路由守卫、刷新恢复、普通用户/管理员分流，以及 Hash 路由的部署原因 `[核验]`。

## 6. 关键交互

### 6.1 推荐查询

表单校验 → 加载 → 冲稳保 → 院校详情 → 加入目标志愿表。说明用户如何知道数据年份和推荐依据。

### 6.2 Agent 工作区

说明会话列表、快速提问、消息区、工具结果、当前操作志愿表和方案预览的状态所有权。关键写操作必须显示目标方案。

### 6.3 What-if 对比（实现后填写）

| 变化 | 表现 |
| --- | --- |
| 新增候选 | 绿色/“新增”文本 |
| 移除候选 | 删除线/“移除”文本 |
| 档位变化 | 原档 → 新档 + 原因 |
| 条件变化 | 顶部显示 old → new |

## 8. 可用性与可访问性

- 键盘导航和焦点可见；
- 表单 label 与错误对应；
- 颜色之外有文本；
- 常见桌面宽度无重叠、溢出和按钮截断；
- 长校名、长专业名、空数据和大数字测试；
- 截图前验证 1280×720、1600×900，移动端仅在实际支持时声明。

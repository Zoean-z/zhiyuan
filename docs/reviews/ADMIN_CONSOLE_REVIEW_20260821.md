# 管理员界面初审与复审记录（2026-08-21）

## 初审范围

- 信息架构是否覆盖实际管理任务
- 工作台指标是否有真实接口与数据库来源
- 管理权限和退出登录是否形成闭环
- 空数据、缺失值、超时、401 等异常状态
- CRUD 与筛选、分页、刷新之间的交互一致性
- 桌面端布局、窄屏降级与基础可访问性

## 初审发现

| 编号 | 级别 | 问题 | 影响 |
| --- | --- | --- | --- |
| R1 | 高 | 管理端退出只清理本地令牌，没有复用应用层退出流程 | 服务端令牌可能未及时失效 |
| R2 | 中 | 考生档案完整度把管理员计入分母 | 指标语义不准确 |
| R3 | 中 | 空院校、空专业、空普通用户时显示“均已完成” | 空状态被误判为健康状态 |
| R4 | 中 | 管理请求没有超时控制 | 单个接口挂起会让工作台持续加载 |
| R5 | 中 | 侧栏最新年份读取当前筛选列表 | 局部筛选结果可能覆盖平台级状态 |
| R6 | 低 | 激活导航缺少 `aria-current`，存在未使用图标导入 | 可访问性与代码质量不足 |

## 整改结果

- R1：优先调用 `workspace.logout()`，复用 `/api/auth/logout`、状态清理与路由跳转完整流程；保留独立挂载时的本地兜底。
- R2：档案完整度只统计 `USER` 角色，管理员不再进入考生分母。
- R3：为无院校、无专业和无普通用户分别提供“待录入/待产生”状态，并跳转到正确的前置模块。
- R4：所有管理请求增加 15 秒 `AbortController` 超时和明确提示。
- R5：工作台首次全量加载后保存平台快照，模块筛选不再改写侧栏全局年份和省份数。
- R6：激活导航增加 `aria-current="page"`，刷新按钮增加 `aria-label`，删除无用导入。

## 复审结论

- R1–R6 已全部关闭。
- 未发现阻断合并的高、中级问题。
- 未引入新的后端接口、权限扩大、虚假指标或无业务落点的菜单。
- 当前版本满足“系统化、与现有业务连接、不是空壳”的验收目标，可进入人工验收与合并流程。

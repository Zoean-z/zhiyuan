## 条目区

### L-20260920-07 查大学列表慢 + 失败被伪装成"没有结果"

- **现象**：查大学页响应慢（数据扩到 1,630 所后更明显），且偶发整页"院校 0 所/没有符合条件的院校"。
- **根因**：两层。① 后端 `list()` 每次请求全量重算——全校逐校概率 breakdown + 16 万行级 GROUP BY 计划聚合 + 校线查询，内存分页使**每一页请求都付全额成本**，前端多页串行再乘倍数；② 前端 `apiFetch` 15 秒 AbortController 超时被 catch 后**静默吞掉**，而 SchoolsView 的 loadError 有赋值没渲染——请求失败被伪装成"没有符合条件的院校"，用户无法区分故障与空结果。
- **解决**：① 后端两级缓存——重 SQL 上下文（校线映射+计划聚合，按省+科类，TTL 3 分钟）与排序后全量 items（按全部查询参数，TTL 3 分钟，容量 64 超限清空）；页大小上限 1000。② 前端 size=1000（1,630 所 2 页拉完）+ SchoolsView 渲染 loadError 与 loading 态。实测：冷 1.85s、热 0.04-0.06s；2 页总耗 ≈2s（旧形态 28s+且超时）。
- **预防**：①"内存分页"接口必须配计算缓存或改真服务端分页，二者选一，不允许裸奔；②**异步失败必须有可见反馈**——catch 后的状态要么渲染、要么上报，禁止落入"空结果"分支（Vue 页面评审 checklist 项：每个 catch 分支的去向）；③前端批量拉取的页数上限要随数据量动态评估（数据扩容后重测加载链路），而不是写死循环上限。

### L-20260920-06 全局 MAX(year) 聚合被零星新年份"毒化"（L-03 预言成真）

- **现象**：志愿表候选卡片全部显示"可填专业(0)"，仅个别学校（复旦等）有数；列表接口的 majorCount/planCount 全为 0。
- **根因**：`aggregatePlanByUniversity` 按**全省全局 MAX(admission_year)** 过滤。湖南库中存在用户后导入的 2026 演示行（2,248 行 SIMULATED），把聚合年份顶到 2026——于是只有演示校命中，其余所有真实学校（2024/2025）的计数整体落空。这正是 L-03 预警的"零星补新年份惩罚全体学校"在生产中的第一次成真；叠加前端计数绑定懒加载列表（未点击前恒空），两头都断了。
- **解决**：聚合年份窗口改为**逐校相关子查询**（`MAX(year) WHERE university_id = m.university_id`），每所学校取自己的最新年份；前端计数改 `f.majorList.length || f.school.majorCount || 0`（展开前用后端真实计数，展开后用已加载列表）。验证：列表接口北大=10 专业/319 人；志愿表卡片显示 5/11/17/30/37 等真实计数，零个 (0)。
- **预防**：①**禁止全省/全局 MAX(year) 类聚合**——凡按年份取"最新"一律逐主体（逐校）取；②展示计数与懒加载列表要用同一数据源或明确优先级；③向库写入新年份数据（哪怕演示用途）后，必须跑一遍核心列表接口对账（本例一条 curl 即可发现 majorCount=0）。

### L-20260920-05 前端 mock 时代假数据混入真实数据链路

- **现象**：推荐卡片"可填专业(0)"但下方显示 14 个专业标签；志愿表选完西北工业大学后专业下拉出现中医学/互联网金融等无关专业；卡片标题带"[1164组]"伪装组号。
- **根因**：志愿填报器早期是纯前端 mock（`utils/exploreData` 本地假学校数组 + `seed % 15 + 5` 随机数生成可填专业数/组号/院校代码/硕士点/保研率/历年分数）。后端数据接入后，这些装饰性 computed 没有被替换：下拉 `majorOptions` 只按批次过滤全量目录、从不按校过滤；计数用推荐项的空字段 `majorCount`；"[组]"是把大学 id 补零伪装的。本质是**渐进迁移时没有逐一核对每个展示字段的数据源**，真数据与假数据在同一张卡片上共存。
- **解决**：下拉改为 `majorsForRow(slot)` 按校读真实接口缓存；删假组号；计数用真实列表长度；推荐卡片清除全部 seed 随机 computed，元信息行改用真实字段，历年表只展示当年真实行（缺失显示"—"）。用 API 直查验证（西工大湖南物理 16 个真实专业零混入）。
- **预防**：①任何展示字段上线前问一句"这个值从哪来"——来源必须是后端字段或明确标注的静态知识，禁止 `seed/random` 进入展示层（可在 CI 加正则扫描 `% 15 +`、`Math.random` 等模式于 src 目录）；②mock 数据结构（exploreData）在真实接口就绪后应整体删除而非并存；③新组件评审时把"每个绑定值的数据源"作为 checklist 项。

### L-20260920-04 SPA 子路由刷新返回 JSON 错误

- **现象**：直接访问/刷新 `/#/rank`、`/schools/41` 等子路由时页面变白屏或一个裸 JSON 框（`RESOURCE_NOT_FOUND: rank`）；用户描述为"右侧跳出框""排行显示半天"。
- **根因**：前端 Vue Router 使用 history 路径，但 Spring Boot 没有 SPA fallback——非 `/api` 且无静态文件的路径全部落进 404 处理器返回 JSON。开发时永远从首页点进子路由（客户端路由切换不发请求），所以刷新场景从未被测过。**"部署形态下的直接访问"是前端测不到的盲区。**
- **解决**：新增 `SpaForwardController`，把前端路由白名单 forward 到 `/index.html`；`/api/**` 与带点号的静态资源不受影响。
- **预防**：①SPA 项目上线 checklist 必含"逐路由直接访问+刷新"；②路由白名单与前端 router/index.js 的 path 清单同步维护（新增前端路由时同步改后端白名单），可在前端构建脚本里做一致性校验；③后端 404 响应体是 JSON 时，考虑对 Accept: text/html 的请求返回 HTML 404 页而非裸 JSON。

### L-20260920-03 数据导入后"没生效"的多重静默成因

- **现象**（历史多次）：明明向库里插了数据，页面查询结果不变；不同环境/不同时间表现不一致。
- **根因**：四个独立成因叠加，每个都静默：① seed 文件（sql/data.sql）只对**空数据卷首次初始化**生效，改它对运行库无效；② 两套并行 MySQL（zhiyuan3/zhiyuan6）插错库；③ Redis 位次/推荐缓存 TTL 内返回旧值（meta 30min/recommendation 10min/目录缓存 5min）；④ 查询契约不匹配——省份串/科类值/年份窗口/外键任一不满足即被 WHERE 静默过滤（如 subject_type 写 'PHYSICS' 永不命中 '物理'；校情年份子查询取全局 MAX(year)，零星补新年份会让其他学校整体落空）。
- **解决**：确立"探针验证法"——导入后插一行可识别的探针数据，用与生产完全相同的入口（页面/API）确认可见，再删除；导数后按缓存类别主动清 Redis 键；跨年导入保持 (省,科类,年份) 整批对称。
- **预防**：①任何数据导入脚本末尾附上验证 SQL+API 冒烟步骤（对账而非"插入成功"）；②键值枚举（省份/科类/批次）集中声明成常量，导入器与查询共用一份；③写年份相关查询时显式回答"某校缺最新年会怎样"，避免全局 MAX 隐式惩罚；④部署文档写明缓存 TTL 清单与清理命令。

### L-20260920-02 CSV→SQL 导入管线的三个坑

- **现象**：导入中断/数据丢失/行数对不上。
- **根因**：① 跨省去重键漏维度（一分一段 dedup key 少了 province，六省同分互相覆盖，6281 行只剩 1398）；② 中文标点全/半角不一致（"（205）"vs"205"组号、"中国地质大学（北京）"vs"(北京)"）导致关联失败与重复入库；③ 引号内含逗号的 CSV 用 awk 按逗号切列会错位（把分数当科类统计）；④ 字段超长（CSV 破损行拼出 120+ 字符专业名）触发 `Data too long` 中断整个事务。
- **解决**：所有 CSV 解析一律用 csv 模块（结构化字段访问）；归一函数统一全角→半角；dedup/关联键显式列出全部维度并写测试；插入前加长度守卫跳过脏行；管线输出统计行（source/dedup/miss）供对账。
- **预防**：①导入管线模板化：esc/num/norm/read_rows 四件套直接复用；②每次导入前后跑"对账 SQL"（总数、按省、按年、唯一键重复、孤儿行），数字对不上禁止继续；③脏行守卫默认开启而非事后补。

### L-20260920-01 双构造器无 @Autowired 导致 Spring 装配失败（同一坑踩两次）

- **现象**：新增带测试构造参数的组件（AgentIntentLexicon / AgentMajorCatalogService）后，单元测试全绿，但 @SpringBootTest 全批 500，根因 `No default constructor found`。
- **根因**：类同时存在公开构造器与包级测试构造器，Spring 在多构造器且无注解时不知道选哪个。单测直接 new 不经过容器，所以测试拦不住装配问题——**测试路径覆盖 ≠ 容器装配覆盖**。
- **解决**：公开构造器加 `@Autowired` 注解。
- **预防**：①任何类出现第二个构造器时，Spring 用的那个必须显式 `@Autowired`（写进编码约定）；②新增 Spring 组件时至少跑一次 @SpringBootTest 上下文加载冒烟（本项目已有 AgentControllerTest 等可承载），而不是只跑纯单测。

### L-20260920-00 工具重载互相递归（StackOverflowError）

- **现象**：给 `UniversityTagUtils.buildSchoolTags` 加 tagsColumn 重载后，全量测试 26 个用例瞬间失败，堆栈全是两个重载互相调用。
- **根因**：为了"复用"让 5 参重载调 4 参、4 参调 5 参，形成环。写的时候只想着复用没画调用方向。
- **解决**：层级标签逻辑内联进 5 参版本，4 参保留为简单委托（单向）。
- **预防**：重载/装饰器链必须保持**单向调用**（旧签名 → 新实现），禁止新实现回调旧签名；JUnit 的 StackOverflow 用例正是价值所在——**全量测试在部署前抓住了它**，坚持改后端必跑全量。

## 原则沉淀

1. **每个展示值都要能回答"数据从哪来"**：后端字段 / 标注的静态知识 / 明确的 UI 装饰，三者之外不允许存在第四种（随机数、写死占位）。
2. **测试路径 ≠ 运行路径**：单元测试 new 出来的对象证明不了容器装配、SPA 刷新、缓存过期、生产端口这些"部署形态"问题——验收清单必须包含部署形态的冒烟（直连 API + 浏览器主流程）。
3. **数据导入的标准闭环**：备份 → 幂等导入（唯一键 + ON DUPLICATE/NOT EXISTS）→ 对账 SQL（总数/分布/重复/孤儿）→ 与生产同入口的探针验证 → 缓存清理 → 独立审查员只读复核。任何一环缺失都可能造成"填了没用"的静默失败。
4. **迁移到真实数据时，mock 的删除是任务的一部分**：接口就绪≠迁移完成，逐字段核对展示层绑定才算完成。
5. **静默过滤是数据类 bug 的温床**：WHERE 条件、缓存、年份窗口、键值格式每一层都会无声地吞数据；设计时让"空结果"尽量带着原因（日志/标注），验证时用对账数字说话。

### L-20260921-08 Agent 问"它的XX专业怎么样"答非所问 + 学校专业表出现重复专业

- **现象**：用户在上轮聊了中南大学后问"它的电子信息工程专业怎么样"，Agent 却调用 getSchoolDetailByName 倒出该校整张专业表（临床医学刷屏、电子信息工程不可见）；且列表标题"可参考专业（共 273 个）"中"临床医学"出现多次（河南/河北/广东的 675/664/662）。
- **根因**：两个独立缺陷叠加。① 路由分支顺序：decideLocally 的"对话续槽"分支（schoolPronouns"它的"+detailNouns"专业"+pronounFollowIntents"怎么样"）排在专业问询判断之前，消息里被提取出的具体专业名（电子信息工程）被无视；"第一个学校的…"序号场景同理。② 数据链路：AgentToolFacade 给 SchoolDetailService 传的是 `SubjectType.name()`（'PHYSICS'），而 major_admission_cutoff 库里存中文（'物理'），第一条 SQL 静默落空后走了**丢弃 province+subject 过滤的宽松回退**，把该校全国所有省份/科类/年份 273 行当"该校可参考专业"返回（DB 对账：回退=273 行，前三名恰为截图中的河南 675/河北 664/广东 662 临床医学；前端 Controller 路径一直传 getDbValue() 故页面无此 bug——同一服务两个调用点一个对一个错，正是 L-03"静默过滤"模式的再现）。
- **解决**：① "专业介绍"判断块整体上移到学校详情类分支之前——消息带具体专业名+概览语气时答专业本身（getMajorOverview）；同时把 majorOverviewExclusions 里的"院校/学校"移除（它们对已提取出具体专业名的问询是误伤，"第一个学校的临床医学专业怎么样"不再被字面排除），新增 detailQueryVerbs 词组修复 P0 #5 的死条件。② AgentToolFacade 两处改用 `getDbValue()`；SchoolDetailService 两条 SQL 加 ROW_NUMBER() PARTITION BY 显示专业名、按最新年份/最优分数取 rn=1（"临床医学"与"临床医学类"名字不同不合并），agent 与前端两条路径行为对齐。验证：同消息复现路由 getMajorOverview；学校详情 273→52 个去重专业；271 测试全绿（含 4 个新路由回归用例，子智能体两场景审查通过）。
- **预防**：① 同一张表的同一过滤条件，参数转换必须收敛到唯一出处（枚举的 getDbValue()），新调用点 code review 时把"传的是 name() 还是 dbValue()"当作固定检查项——两个调用点一成一个错说明转换散落在调用方，理想做法是 SchoolDetailService 收窄为接收 SubjectType 枚举自行转换；② "过滤落空→宽松回退"的回退必须带可观测标记（日志/summary 注明"该省份暂无数据，以下为其他省份参考"），否则数据错误被伪装成正常结果（L-03/L-07 同族）；③ 路由分支的优先级语义要写成测试：带具体专业名的问询优先于学校详情，没有具体专业名时维持学校详情——本轮 4 个回归用例即是该语义的固化；④ 词表治理测试（coversEveryGroupReferencedByCode）要继续维护最小词条数，代码引用了不存在的组（detailQueryVerbs）意味着静默收窄路由面。

## 固定工作流：主线程-子智能体同步审查验证（bug-hunt）

- **模式**：主智能体把 DEV_ISSUES.md 的 L-01~L-08 沉淀为模式库，派多个子智能体分模块（数据层/前端/Agent决策层/装配部署）并行扫描同族问题 → 分诊统一口径 → 每条由未见过原扫描员的独立复核员复现 → 确认的高中危项由修复员最小修复并反复过全量测试 → 独立审查员复核全部 diff → 构建部署 → 线上只读冒烟 → 结果沉淀回 DEV_ISSUES/PROJECT_LOG。主智能体另在本机浏览器做真实点击级 UI 验证（工作流之外执行）。
- **执行方式**：项目级 workflow `zhiyuan-bug-hunt`（.zcode/workflows/zhiyuan-bug-hunt.dwf.ts），用 CreateWorkflow `saved: { name: "zhiyuan-bug-hunt" }` 运行；重复运行无害。
- **纪律**：复核员与扫描员必须隔离上下文；修复必须同步配测试；设计取舍声明而不是擅自决定；unconfirmed 项保留并标注，不静默丢弃。

# 智愿AI报考系统 · 项目设计文档

> 本文档原为英文设计稿（2026-06），2026-09-20 由项目根迁入 `docs/project/` 并整体译为中文；第 15 章升级路线与文末"项目计划"保留历史原貌。文中 API/字段/代码名保持英文原样。

## 1. 项目概述

构建一个 Web 端 AI 高考志愿推荐系统，用户输入：

- 高考分数
- 省份
- 科类（如 物理类 / 历史类）

系统按以下三档返回推荐院校：

- `冲`（Rush，激进冲刺）
- `稳`（Safe，稳健匹配）
- `保`（Guarantee，保守兜底）

同时调用 AI API 为每条推荐生成解读文本，并在 Vue3 + Element Plus 界面中展示。

---

## 2. 技术栈

- 后端：Spring Boot 3.x
- 前端：Vue3 + Vite + Element Plus
- 数据库：MySQL 8.x
- ORM：MyBatis-Plus 或 Spring Data JPA（推荐 MyBatis-Plus，SQL 可控性强）
- AI 集成：OpenAI 兼容 Chat Completion API
- 构建工具：Maven（后端）、npm/pnpm（前端）

## 3. 总体架构

### 3.1 组成部分
- **前端（Vue3）**
  - 输入表单：分数、省份、科类
  - 结果页：冲/稳/保分组推荐
  - AI 解读面板
- **后端（Spring Boot）**
  - 推荐请求 REST API
  - 推荐引擎（基于策略的过滤与打分）
  - AI 解读服务
  - 院校数据与查询日志的持久层
- **MySQL**
  - 院校录取历史
  - 分省/分科类投档线数据
  - 用户查询记录与推荐结果缓存（可选）

### 3.2 请求流程
1. 前端提交表单。
2. 后端校验请求。
3. 推荐引擎计算冲/稳/保三组结果。
4. 后端携带推荐上下文调用 AI API。
5. 后端返回推荐结果 + AI 解读。
6. 前端渲染结果卡片与策略页签。

## 4. 功能需求

### 4.1 输入
- 必填字段：
  - 分数（整数）
  - 省份（枚举/字符串）
  - 科类（枚举：按地区规则为 物理/历史 或 理科/文科）

### 4.2 推荐输出
- 至少返回：
  - 院校名称
  - 专业组（可选）
  - 预估录取概率
  - 策略标签（`RUSH` / `SAFE` / `GUARANTEE`）
  - 历史分差数据
  - AI 生成的推荐理由

### 4.3 策略逻辑
- `冲`：分数接近或略低于近年投档线（高风险高回报）
- `稳`：分数适度高于投档线（均衡）
- `保`：分数明显高于投档线（把握大）

建议分差阈值（可按省份与科类配置）：
- 冲：`考生分 - 投档线 ∈ [-10, +5]`
- 稳：`考生分 - 投档线 ∈ [+6, +20]`
- 保：`考生分 - 投档线 ≥ +21`

---

## 5. 非功能需求

- 性能：无 AI 单次推荐 < 2s，含 AI < 5s
- 可靠性：AI API 故障时优雅降级（返回无解读的推荐结果）
- 安全：基础 API 认证（JWT）、参数校验、AI 接口限流
- 可扩展：后端无状态，热门推荐可选 Redis 缓存
- 可观测：请求日志、推荐链路日志、AI 调用耗时/错误指标

## 6. 后端设计（Spring Boot）

### 6.1 模块结构
- `controller`
  - `RecommendationController`
- `service`
  - `RecommendationService`
  - `StrategyClassifierService`
  - `AiExplanationService`
- `repository/mapper`
  - 院校与投档线数据访问
- `model`
  - 实体、DTO、VO、枚举
- `config`
  - AI 客户端配置、CORS、异常处理

### 6.2 核心 API

### POST `/api/recommendations`
请求：
```json
{
  "score": 612,
  "province": "Zhejiang",
  "subjectType": "PHYSICS"
}
```

响应：
```json
{
  "requestId": "uuid",
  "rush": [],
  "safe": [],
  "guarantee": [],
  "summary": "AI 生成的总结"
}
```

### GET `/api/meta/options`
- 返回表单渲染所需的省份列表与科类选项。

### 6.3 推荐引擎
- 第 1 步：按省份 + 科类查询候选院校。
- 第 2 步：计算特征——
  - 近三年平均投档线
  - 分差
  - 波动性
  - 录取趋势
- 第 3 步：计算录取概率（先规则实现，可扩展为 ML 模型）。
- 第 4 步：按可配置阈值打策略标签。
- 第 5 步：组内排序并返回 Top N（如每组 5 条）。

### 6.4 AI 解读服务
- 提示词包含：
  - 用户画像（分数/省份/科类）
  - 候选院校及其分差/概率
  - 要求的输出格式（每校一句理由 + 总体建议）
- 超时与重试策略：
  - 超时：3s
  - 重试：1 次
  - 兜底：静态模板解读

## 9. 推荐策略细节

### 9.1 打分公式（初期规则版）
`finalScore = w1 * gapScore + w2 * stabilityScore + w3 * trendScore`

- `gapScore`：归一化分差
- `stabilityScore`：年度投档线方差的倒数（越稳越高）
- `trendScore`：近年录取趋势利好度

建议初始权重：
- `w1 = 0.6`
- `w2 = 0.25`
- `w3 = 0.15`

### 9.2 排序
- 每个策略组内按：
  1. 录取概率（降序）
  2. 院校层次（降序，可选）
  3. 近年波动性（升序）

## 10. AI 提示词设计

系统提示词目标：
- 解释每所院校为何落在冲/稳/保
- 明确说明分差与风险
- 语言简洁，学生易懂
- 避免任何"保证录取"的表述

期望输出格式：
- 总体建议（3-5 行）
- 每校解读（每校 1-2 行）

---

## 11. 错误处理与降级

- 参数非法：返回 `400` 并给出字段级错误信息
- 无候选数据：返回空分组 + 说明
- AI API 故障：返回推荐数据 + 兜底解读
- 数据库超时：返回 `503` 与链路追踪 ID

## 15. 升级路线（2026-06）

### 阶段一 · 低风险补全
- 保持单体 Spring Boot 架构。
- 不引入微服务、MQ 或分布式中间件。
- 聚焦把当前架构补完整：
  - 统一响应格式
  - 稳定的异常与错误码处理
  - 请求校验与参数规范化
  - 按环境拆分配置
- 围绕真实业务流升级持久化模型：
  - 考生画像
  - 推荐任务
  - 推荐结果
  - AI 解析日志
  - 更丰富的录取统计
- 推荐逻辑从固定分差/位差阈值升级为基础规则打分模型：
  - 先计算概率或风险分
  - 再映射到冲/稳/保
  - 解读全程服务端可控

### 阶段二 · 后端纵深与简历价值
- 引入 Redis：
  - 热门院校/专业/位次映射缓存
  - 热门推荐缓存
  - token/验证码/限流支撑
  - AI 重复请求防护
- 认证升级：
  - Spring Security
  - JWT
  - BCrypt 密码哈希
  - 用户/管理员角色分离
- 扩充用户侧持久化：
  - 推荐历史
  - 收藏方案
  - 解读记录
- 增加管理端维护：院校、专业、录取数据。

### 阶段三 · 工程成熟度
- AI 解析与推荐报告生成支持异步任务。
- 针对省份/年份/科类/院校/专业/位次查询优化 SQL 与索引。
- 增加 Docker Compose 本地部署。
- 完善测试：
  - service 测试
  - controller 集成测试
  - 可选的 repository/数据测试
- 增加可观测性：
  - 结构化日志
  - 请求追踪 ID
  - 慢查询 / AI 耗时监控

### 策略升级说明
- 当前实现主要按硬编码的 `scoreGap` 与 `rankGap` 区间分桶。
- 实现简单，但作为长期推荐引擎偏弱，无法表达：
  - 年度波动
  - 偏好匹配
  - 综合置信度/风险
  - 更可解释的排序
- 更好的基线是：
  - 先按硬性约束过滤候选院校/专业
  - 计算规则化推荐分与录取概率
  - 将概率区间映射为冲/稳/保
  - 每条结果返回解读字段

# 管理员界面系统化设计（2026-08-21）

## 1. 基线审查

目标基线：`feature/real-data-20260821`。

仓库已经存在管理接口和一个基础 `AdminView.vue`，但原页面更接近把五组 CRUD 平铺到公共顶部导航中，缺少管理工作台、跨模块数据状态、业务运行指标和缺口引导，因此容易给人“有入口但没有管理系统”的感觉。

已确认的真实后端边界：

- 用户：`/api/admin/users`、`/api/admin/users/overview`、`/api/admin/users/{id}/settings`
- 院校：`/api/admin/universities`
- 专业：`/api/admin/majors`
- 院校录取线：`/api/admin/admission-cutoffs`
- 专业录取线：`/api/admin/major-admission-cutoffs`
- 角色约束：所有 `/api/admin/**` 接口只允许 `ADMIN`；当前管理员不能停用或降级自己

本轮没有增加不存在的“运营收入”“实时在线人数”“AI 模型开关”等空壳模块。

## 2. 信息架构

### 业务总览

- 管理工作台
  - 用户、院校、专业、录取事实数据四类核心规模
  - 推荐记录、志愿方案、AI 会话三类业务使用量
  - 院校录取数据覆盖率、专业录取数据覆盖率、考生档案完整度
  - 基于真实缺口自动生成的待处理事项
  - 最新院校录取数据

### 账号与内容

- 用户管理：筛选账号，查看报考资料与业务计数，维护角色和启停状态
- 院校管理：维护推荐与查询使用的院校主数据
- 专业管理：维护专业分类、选科要求、标签和说明

### 招生数据

- 院校录取线：按院校、年份、省份、科类查询和维护
- 专业录取线：按院校、专业、年份、省份、科类查询和维护

## 3. 与现有系统的连接

1. **指标不造数**：工作台通过六个既有管理接口并行获取数据库结果，再在前端做可复核的集合统计。
2. **业务计数有来源**：推荐记录、志愿方案和 AI 会话取自管理员用户响应中的对应计数字段。
3. **数据覆盖可行动**：覆盖率由主数据 ID 与录取数据关联计算；点击缺口项直接进入对应维护模块。
4. **修改立即生效**：所有新增和编辑继续调用既有后端服务，不绕开数据库或推荐业务边界。
5. **概念保持一致**：沿用目标分支“211 并入双一流”的显示规则，同时兼容后端现有 `is211` 字段。
6. **缺失值不伪造**：最低分、最低位次缺失时显示 `—`，不填默认值。

## 4. 视觉与交互决策

上传参考图提供了有效的管理端骨架：左侧模块导航、顶部身份区、概览卡、筛选区、数据表与分页。本实现吸收该结构，但不机械复制：

- 使用项目既有品牌组件、字体和高考主题插画；
- 以项目现有橙色为主操作色、蓝色为数据辅助色，避免形成第二套产品；
- 独立管理侧栏承载模块导航，公共用户导航不再与管理任务混用；
- 工作台先展示“状态与缺口”，CRUD 页面继续保持筛选—列表—编辑的稳定结构；
- 桌面优先，同时为 1380px、900px、680px 三档宽度提供响应式布局。

## 5. 安全与权限

- 路由继续使用 `requiresAdmin` 守卫；
- 请求继续携带 JWT；401 时清理本地会话并返回登录页；
- 不在前端显示或处理密码；
- 当前管理员的角色与启停控件保持禁用，后端同时二次校验；
- 没有新增删除用户、批量覆盖录取数据等高风险操作。

## 6. 验收范围

- 管理员登录后默认进入管理工作台；
- 六类真实数据能在工作台形成规模、使用量、覆盖率和待处理项；
- 用户、院校、专业、两类录取线均可查询；四类基础数据可新增/编辑；
- 用户角色与启停可维护，且不能修改当前管理员自身安全边界；
- 所有模块共享同一管理侧栏、顶部身份区和视觉令牌；
- 不出现无接口支撑的菜单、按钮或指标。

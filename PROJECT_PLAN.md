# AI College Recommendation System - Project Design

## 1. Project Overview

Build a web-based AI college recommendation system where users input:
- Exam score
- Province
- Subject type (e.g., Physics track / History track)

The system returns recommended universities using:
- `Rush` (aggressive)
- `Safe` (balanced)
- `Guarantee` (conservative)

It also calls an AI API to generate explanation text for each recommendation and displays results in a Vue3 + ElementPlus UI.

---

## 2. Tech Stack

- Backend: Spring Boot 3.x
- Frontend: Vue3 + Vite + ElementPlus
- Database: MySQL 8.x
- ORM: MyBatis-Plus or Spring Data JPA (recommended: MyBatis-Plus for SQL control)
- AI Integration: OpenAI-compatible Chat Completion API
- Build Tools: Maven (backend), npm/pnpm (frontend)

---

## 3. High-Level Architecture

## 3.1 Components
- **Frontend (Vue3)**
  - Input form: score, province, subject type
  - Result page: grouped recommendations (Rush/Safe/Guarantee)
  - Explanation panel generated by AI
- **Backend (Spring Boot)**
  - REST API for recommendation requests
  - Recommendation engine (strategy-based filtering and scoring)
  - AI explanation service
  - Persistence layer for university data and query logs
- **MySQL**
  - University admission history
  - Province/subject cutoff data
  - User query records and recommendation results cache (optional)

## 3.2 Request Flow
1. User submits form in frontend.
2. Backend validates request.
3. Recommendation engine computes Rush/Safe/Guarantee sets.
4. Backend calls AI API with recommendation context.
5. Backend returns recommendations + AI explanations.
6. Frontend renders result cards and strategy tabs.

---

## 4. Functional Requirements

## 4.1 Input
- Required fields:
  - Score (integer)
  - Province (enum/string)
  - Subject type (enum: Physics/History or Science/Arts by region rule)

## 4.2 Recommendation Output
- Return at least:
  - University name
  - Major group (optional)
  - Estimated admission probability
  - Strategy tag (`RUSH`, `SAFE`, `GUARANTEE`)
  - Historical score gap data
  - AI-generated recommendation reason

## 4.3 Strategy Logic
- `Rush`: score close to or slightly below recent cutoff (high risk, high reward)
- `Safe`: score moderately above cutoff (balanced)
- `Guarantee`: score clearly above cutoff (high chance)

Suggested score-gap thresholds (configurable by province and subject):
- Rush: `userScore - cutoff in [-10, +5]`
- Safe: `userScore - cutoff in [+6, +20]`
- Guarantee: `userScore - cutoff >= +21`

---

## 5. Non-Functional Requirements

- Performance: single recommendation request < 2s without AI, < 5s with AI
- Reliability: graceful fallback when AI API fails (return recommendations without explanation)
- Security: basic API auth (JWT), parameter validation, rate limit for AI endpoint
- Scalability: stateless backend, optional Redis cache for hot recommendation requests
- Observability: request logs, recommendation trace logs, AI call latency/error metrics

## 6. Backend Design (Spring Boot)

## 6.1 Module Structure
- `controller`
  - `RecommendationController`
- `service`
  - `RecommendationService`
  - `StrategyClassifierService`
  - `AiExplanationService`
- `repository/mapper`
  - University and cutoff data access
- `model`
  - Entity, DTO, VO, enums
- `config`
  - AI client config, CORS, exception handling

## 6.2 Core API

### POST `/api/recommendations`
Request:
```json
{
  "score": 612,
  "province": "Zhejiang",
  "subjectType": "PHYSICS"
}
```

Response:
```json
{
  "requestId": "uuid",
  "rush": [],
  "safe": [],
  "guarantee": [],
  "summary": "AI generated summary"
}
```

### GET `/api/meta/options`
- Return province list and subject-type options for form rendering.

## 6.3 Recommendation Engine
- Step 1: Query candidate universities by province + subject type.
- Step 2: Compute features:
  - 3-year average cutoff
  - score gap
  - volatility
  - admission trend
- Step 3: Compute admission probability (rule-based first, extendable to ML model).
- Step 4: Assign strategy tag based on configurable thresholds.
- Step 5: Rank each strategy group and return Top N (e.g., 5 each).

## 6.4 AI Explanation Service
- Input prompt includes:
  - User profile (score/province/subject)
  - Candidate schools with score gaps/probabilities
  - Required output format (short reason per school + overall advice)
- Timeout and retry policy:
  - timeout: 3s
  - retries: 1
  - fallback: static template explanation

## 9. Recommendation Strategy Details

## 9.1 Scoring Formula (Initial Rule-Based)
`finalScore = w1 * gapScore + w2 * stabilityScore + w3 * trendScore`

- `gapScore`: normalized score gap
- `stabilityScore`: inverse of yearly cutoff variance
- `trendScore`: recent admission trend favorability

Recommended initial weights:
- `w1 = 0.6`
- `w2 = 0.25`
- `w3 = 0.15`

## 9.2 Sorting
- Within each strategy group, sort by:
  1. Admission probability (desc)
  2. School quality/tier (desc, optional)
  3. Recent volatility (asc)

---

## 10. AI Prompt Design

System prompt goals:
- Explain why each university is in Rush/Safe/Guarantee
- Mention score gap and risk clearly
- Keep language concise and understandable for students
- Avoid guaranteed-admission claims

Expected output format:
- Overall advice (3-5 lines)
- Per-university explanation (1-2 lines each)

---

## 11. Error Handling & Fallback

- Invalid input: return `400` with clear field-level messages
- No candidate data: return empty groups + explanation
- AI API failure: return recommendation data with fallback explanation
- Database timeout: return `503` and trace ID

---

## 12. Security & Compliance

- Validate and sanitize all inputs
- Add JWT-based authentication if user accounts are enabled
- Protect AI API key in backend environment variables
- Do not expose secret keys in frontend
- Add operation logs for auditability

## 15. Upgrade Roadmap (2026-06)

### Phase 1 - Low-risk completion
- Keep the project as a single Spring Boot application.
- Do not introduce microservices, MQ, or distributed middleware.
- Focus on making the current architecture more complete:
  - unified response format
  - stable exception and error-code handling
  - request validation and parameter normalization
  - environment-based configuration split
- Upgrade the persistence model around the real business flow:
  - student profile
  - recommendation task
  - recommendation result
  - AI parse log
  - richer admission statistics
- Upgrade recommendation logic from fixed score-gap / rank-gap thresholds to a basic rule-scoring model:
  - calculate a probability or risk score first
  - then map results into Rush / Safe / Guarantee
  - keep explanation fully server-side and controllable

### Phase 2 - Backend depth and resume value
- Introduce Redis for:
  - hot university / major / rank-mapping cache
  - popular recommendation cache
  - token / verification / rate limit support
  - AI duplicate-request protection
- Upgrade authentication to:
  - Spring Security
  - JWT
  - BCrypt password hashing
  - role separation for user / admin
- Expand user-side persistence:
  - recommendation history
  - saved plans
  - explanation records
- Add admin-side maintenance for university, major, and admission data.

### Phase 3 - Engineering maturity
- Add async task support for AI parsing and recommendation report generation.
- Optimize SQL and indexes for province / year / subject / university / major / rank queries.
- Add Docker Compose for local deployment.
- Improve testing:
  - service tests
  - controller integration tests
  - optional repository/data tests
- Add observability:
  - structured logs
  - request trace id
  - slow query / AI latency tracking

### Strategy upgrade note
- The current implementation mainly buckets schools by hardcoded `scoreGap` and `rankGap` ranges.
- That is easy to implement, but weak as a long-term recommendation engine because it cannot express:
  - year-over-year fluctuation
  - preference match
  - combined confidence / risk
  - more explainable ranking
- A better baseline is:
  - filter candidate schools/majors by hard constraints
  - compute a rule-based recommendation score and admission probability
  - map probability bands into Rush / Safe / Guarantee
  - return explanation fields for each result
